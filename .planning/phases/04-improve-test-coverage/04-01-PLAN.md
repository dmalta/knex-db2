  <files>tests/unit/client.test.js</files>
  <behavior>
    - acquireRawConnection success: driver.open calls back with (null, conn) → resolves with conn stamped with __knex__acquired, __knex__db2_client, __knex__autocommit
    - acquireRawConnection error: driver.open calls back with (err, null) → rejects with DB2Error
    - acquireRawConnection timeout: driver.open never calls back → rejects with "Connection timeout" after N ms (use a very short timeout to keep tests fast — set config.connection.connectionTimeout = 50)
    - buildConnectionString minimal: DATABASE, HOSTNAME, PORT, PROTOCOL, UID, PWD present
    - buildConnectionString with all optional params: schema → CURRENTSCHEMA=; security:'SSL' → SECURITY=SSL; connectTimeout → CONNECTTIMEOUT=; queryTimeout → QUERYTIMEOUT=
    - buildConnectionString uses settings.uid fallback when settings.user absent
    - setConnectionOptions with autocommit:false stamps __knex__autocommit = false
    - setConnectionOptions default (autocommit not set) stamps __knex__autocommit = true
    - destroyRawConnection resolves when close() succeeds
    - destroyRawConnection resolves immediately for already-disposed connections
    - destroyRawConnection rejects with enhanced error when close() calls back with error
  </behavior>
  <action>
    Append a new `describe('Connection lifecycle', ...)` block to the existing `tests/unit/client.test.js`.

    To mock `driver.open` without touching the real ibm_db module, patch `client.driver.open` (a
    plain function on the module object already loaded) with `vi.fn()` before each test, and
    restore it after.


  <name>Task 2: Query execution paths — _executeDML positive SQLCODE, _executeDDL suppressIfNotFound, _executeQuery errors, query timeout, processResponse</name>
  <files>tests/unit/client.test.js</files>
  <behavior>
    - _executeDML positive SQLCODE (+513): executeNonQuery throws { sqlcode: 513 } → connection.__knex__disposed=true, obj.rowCount=0, resolves (no throw)
    - _executeDML negative SQLCODE: executeNonQuery throws { sqlcode: -803 } → rejects with enhanced error
    - _executeDML closeSync called even when executeNonQuery throws
    - _executeDDL suppressIfNotFound=true + error.sqlcode=-204 → resolves (rowCount 0)
    - _executeDDL suppressIfNotFound=true + error.sqlcode=-000 → rejects (non-204 error propagates)
    - _executeDDL suppressIfNotFound=false → rejects on any executeNonQuery error
    - _executeQuery fetchAllSync throws → rejects with enhanced error; result.closeSync() still called
    - _executeQuery success returns { response: rows, rowCount: rows.length }
    - query() with queryTimeout=50: patch executeQuery to never resolve, advance timers → rejects "Query timeout after 50ms"
    - processResponse null → returns undefined
    - processResponse method='select' → returns response array
    - processResponse method='first' → returns response[0]
    - processResponse method='pluck' → returns response.map(r => r[obj.pluck])
    - processResponse method='insert' with returning → returns response
    - processResponse method='del' without returning → returns obj.rowCount
    - processResponse method='update' without returning → returns obj.rowCount
    - processResponse method='counter' without returning → returns obj.rowCount
    - processResponse with obj.output → calls obj.output.call(runner, response)
    - processResponse unknown method → returns response
  </behavior>
  <action>
    Append additional `describe` blocks to `tests/unit/client.test.js`.

    For _executeDML, _executeDDL, _executeQuery call the private methods directly using
    the client instance (these are prototype methods, not private class fields):
    ```js
    const stmt = {
      executeNonQuery: vi.fn(() => Promise.reject({ sqlcode: 513 })),
      closeSync: vi.fn(),
    };
    const obj = { sql: 'DELETE FROM t', bindings: [] };
    const conn = { __knex__disposed: false };
    const result = await client._executeDML(conn, stmt, obj);
    expect(conn.__knex__disposed).toBe(true);
    expect(result.rowCount).toBe(0);
    ```

    For _executeDDL suppressIfNotFound:
    ```js
    const stmt = {
      executeNonQuery: vi.fn(() => Promise.reject({ sqlcode: -204 })),
      closeSync: vi.fn(),
    };
    const obj = { sql: 'DROP TABLE X', bindings: [], suppressIfNotFound: true };
    const result = await client._executeDDL(stmt, obj);
    expect(result.rowCount).toBe(0);
    ```

    For _executeQuery fetchAllSync error:
    ```js
    const mockResult = {
      fetchAllSync: vi.fn(() => { throw new Error('fetch failed'); }),
      closeSync: vi.fn(),
    };
    const stmt = {
      execute: vi.fn(() => Promise.resolve(mockResult)),
      closeSync: vi.fn(),
    };
    await expect(client._executeQuery(stmt, { sql: 'SELECT 1', bindings: [] })).rejects.toThrow();
    expect(mockResult.closeSync).toHaveBeenCalled(); // cleanup still runs
    ```

    For query timeout — use vi.useFakeTimers():
    ```js
    vi.useFakeTimers();
    const conn = { prepare: vi.fn(() => new Promise(() => {})), query: vi.fn() }; // never resolves
    const queryPromise = client.query(conn, { sql: 'SELECT 1' });
    vi.advanceTimersByTime(100);
    await expect(queryPromise).rejects.toMatch(/Query timeout/);
    vi.useRealTimers();
    ```
    Create a fresh client with `connection: { queryTimeout: 50 }` for this test.

    For processResponse, call directly:
    ```js
    expect(client.processResponse(null)).toBeUndefined();
    expect(client.processResponse({ method: 'select', response: [1,2] })).toEqual([1,2]);

    ```
