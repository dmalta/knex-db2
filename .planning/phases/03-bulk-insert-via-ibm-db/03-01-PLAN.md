<objective>
Implement the ibm_db column-wise array-insert fast path for multi-row inserts.

Purpose: DB2 z/OS does not support multi-VALUES SQL (e.g. `INSERT INTO t VALUES (...),(...)`)
so the base knex compiler would produce invalid SQL for bulk inserts. The fix intercepts
multi-row insert data at the compiler level, stores it on a private property, then the
driver uses ibm_db's single-call ARRAY parameter mechanism to execute all rows at once.

Output:
- Modified `db2-querycompiler.js` with `insert()` override
- Modified `client.js` with bulk fast-path branch in `query()`
</objective>

ibm_db column-wise array parameter format:
```javascript

const arrayParams = [
  { ParamType: 'ARRAY', DataType: 'INT',     Data: [1, 2, 3] },  // column 0
  { ParamType: 'ARRAY', DataType: 'VARCHAR', Data: ['a','b','c'] } // column 1
];
await connection.query({ sql: insertSql, params: arrayParams, ArraySize: 3 });
```
DataType mapping from JS value type (check first non-null value in each column's Data array):
- number with no fractional part → 'INT'
- number with fractional part    → 'DOUBLE'
- Date instance                  → 'TIMESTAMP'
- Buffer instance                → 'BLOB'
- everything else (string, null, bool, undefined) → 'VARCHAR'

Implementation:

```javascript
insert() {
  const insertValues = this.single.insert || [];
  const insertData = this._prepInsert(insertValues);

  // Fall through for raw SQL inserts or single-row inserts
  if (
    typeof insertData === 'string' ||
    !insertData.columns ||
    !insertData.columns.length ||
    !insertData.values ||
    insertData.values.length <= 1
  ) {
    return super.insert();
  }

  const columns = insertData.columns;
  const placeholders = columns.map(() => '?').join(', ');
  const sql =
    this.with() +
    `insert into ${this.tableName} (${this.formatter.columnize(columns)}) values (${placeholders})`;

  return {
    sql,
    bindings: [],
    __db2BulkInsert: {
      columns,
      values: insertData.values,
    },
  };
}
```

IMPORTANT: `this.formatter.columnize(columns)` wraps each column with `this.wrapIdentifierImpl`
which in Db2QueryCompiler returns identifiers as-is — no extra quoting needed.

Insert this block:

```javascript
// --- Bulk insert fast path (ibm_db column-wise ARRAY params) ---
if (obj.__db2BulkInsert && typeof connection.query === 'function') {
  const { columns, values } = obj.__db2BulkInsert;
  const numRows = values.length;

  // Transpose row-major values[][] → column-major ARRAY params
  const arrayParams = columns.map((col, colIdx) => {
    const columnData = values.map((row) => row[colIdx]);

    // Infer ibm_db DataType from the first non-null JS value
    let dataType = 'VARCHAR';
    const sample = columnData.find((v) => v != null);
    if (sample != null) {
      if (sample instanceof Date) {
        dataType = 'TIMESTAMP';
      } else if (Buffer.isBuffer(sample)) {
        dataType = 'BLOB';
      } else if (typeof sample === 'number') {
        dataType = Number.isInteger(sample) ? 'INT' : 'DOUBLE';
      }
    }

    return { ParamType: 'ARRAY', DataType: dataType, Data: columnData };
  });

  await connection.query({ sql: obj.sql, params: arrayParams, ArraySize: numRows });
  obj.response = [];
  obj.rowCount = numRows;
  return obj;
}
// If __db2BulkInsert is set but connection.query is not available, fall through
// to the serial path below (prepare/executeNonQuery row by row is not supported
// for multi-row at this level — the caller should not reach here without ibm_db).
// --- end bulk fast path ---
```

Place this block so it comes before `const sqlTrimmed = obj.sql.trim().toLowerCase();`
